ЦЕЛЬ ЭТАПА
На любой доске 6x6, 8x8, 10x10 работает выбранное перед партией число пар порталов 0..3. Реализованы свободный выход в начале хода, телепортация скользящих фигур во время хода, ограничения на занятый выход, одна активация за ход, корректная проверка шаха и визуальная обратная связь. Благословения ещё не реализуются.

ЗАДАЧИ

1. Модель порталов
chess/core/portals.py:
- PortalPair: id, color_index, symbol_index, a, b;
- PortalSet или список пар;
- lookup: portal_at(square) -> PortalPair | None, paired_square(square) -> Square | None;
- генератор generate_portals(board, count, rng) -> list[PortalPair]:
  - count 0..3;
  - клетки только свободные на момент генерации;
  - не первый и не последний ранг;
  - клетки внутри пары различны;
  - клетка не может входить в две пары;
  - пары получают разные color_index и symbol_index;
  - поддержка seed/random.Random для тестов.
- Генерация выполняется после начальной расстановки, до первого хода.

2. Состояние
Расширь GameState:
- portals: list[PortalPair];
- выбранное количество порталов сохраняется;
- при клонировании порталы копируются;
- хеш состояния включает раскладку порталов (для повторений).

3. Представление телепортации в ходах
Расширь Move/Turn:
- Move.teleport: PortalActivation | None, где PortalActivation содержит pair_id, entry, exit;
- Turn.free_teleport: PortalActivation | None — свободный выход в начале хода;
- при применении хода:
  - free_teleport выполняется до основного действия;
  - Move.teleport выполняется по пути: from -> entry -> exit -> to;
  - все проверки выполняются до изменения состояния;
  - при ошибке состояние не меняется.
- Одна активация за ход: free_teleport и Move.teleport взаимоисключающи; если free_teleport использован, Move.teleport должен быть None.
- Для будущего двойного хода оставь в Turn список moves, но сейчас ровно один Move.

4. Генерация ходов с порталами
В core:
- Свободный выход:
  - если фигура в начале хода стоит на портале;
  - выход свободен;
  - игрок может выбрать свободный выход;
  - после выхода фигура может сделать обычный ход (включая взятие и превращение для пешки);
  - свободный выход не является отдельным ходом, но расходует единственную активацию;
  - после свободного выхода рокировка невозможна: король или ладья считаются двигавшимися, соответствующие права теряются;
  - любая телепортация выставляет has_moved=True и при необходимости снимает права на рокировку.
- Скользящие фигуры:
  - слон, ладья, ферзь;
  - могут дойти до пустой клетки входа по обычной линии;
  - телепортироваться на свободный выход;
  - продолжить ход из выхода в любом направлении, доступном типу фигуры;
  - взятие только на конечной клетке;
  - можно остановиться на второй клетке портала, но не активировать её;
  - вход должен быть пустым; если на входе враг — это обычное взятие с завершением хода;
  - выход должен быть пустым;
  - не более одной активации за ход.
- Короткие фигуры:
  - король, конь, пешка не телепортируются в середине хода;
  - могут использовать свободный выход в начале следующего хода;
  - после свободного выхода действуют по обычным правилам.
- Пешка:
  - после свободного выхода не может сделать двойной ход;
  - может бить на проходе и превращаться по обычным правилам.
- Король:
  - не может телепортироваться на клетку, атакованную противником;
  - итоговая позиция должна быть безопасной.
- Рокировка не активирует порталы.
- Запрещено активировать портал, если выход занят любой фигурой.
- Запрещено телепортироваться, если клетка входа занята (кроме обычного взятия с завершением хода).

5. Шах и атаки
- is_in_check / attack generation должны учитывать:
  - атаку скользящей фигуры через портал (она может телепортироваться и взять короля);
  - атаку фигуры, стоящей на портале, после свободного выхода;
  - атаку после свободного выхода короткой фигуры.
- Порталы не должны ломать обычные атаки, блокировки и мат.
- Убедись, что проверка шаха не создаёт бесконечной рекурсии: атаки через портал считаются один раз, без повторной активации.
- Связанные фигуры и обычные ограничения сохраняются.

6. UI
- BoardView рисует порталы:
  - цветное кольцо/спираль;
  - символ пары (спираль, треугольник, звезда);
  - цвета: циан, маджента, янтарь;
  - не перекрывает фигуру, но хорошо заметен на пустой клетке.
- При наведении на портал — подсказка: «Портал <цвет>: связан с e5».
- При выборе фигуры:
  - если доступен свободный выход, выход подсвечивается цветом пары и специальным маркером; клик по выходу выполняет свободный выход, фигура остаётся выбранной, далее показываются её обычные ходы из выхода;
  - правый клик/Esc отменяет свободный выход и возвращает фигуру;
  - если доступны ходы с телепортацией, конечные клетки показываются как обычные легальные ходы с кольцом цвета портала;
  - при наведении на такой ход можно показать пунктирный путь от входа к выходу (опционально, но желательно).
- Анимация телепортации: короткое исчезновение/появление или вспышка; не должна блокировать ввод.
- Журнал: базовые записи с «~» (a1-a4~h4-h8, b3~g6-g7); полный журнал — этап 6.
- Панель показывает количество порталов.
- Клик по выходу не должен восприниматься как обычный ход, если это свободный выход.
